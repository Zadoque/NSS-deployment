\subsection{Pendências críticas explícitas}

\begin{enumerate}
    \item validar a base/código exato de Toxoplasmose antes de expor essa doença como disponível;
    \item validar, por doença, quando uma notificação pode ser chamada de caso confirmado;
    \item corrigir os achados críticos do CNES/pipeline antes de confiar em territorialização por unidade notificadora.
\end{enumerate}

A pendência de definição de ``caso'' possui fallback semântico seguro: mostrar \textbf{Notificações}. A pendência de Toxoplasmose não possui fallback: se não for validada, a doença não deve ser anunciada como disponível.

\subsection{Definition of Done}

A NSS 1.0 somente é considerada pronta quando:

\begin{itemize}
    \item autenticação por e-mail/senha funciona;
    \item access token, refresh rotacionável e logout funcionam;
    \item \texttt{/mapa} não é acessível sem autenticação;
    \item auto-registro público e CRUD irrestrito de usuários não estão expostos;
    \item pipeline produz Gold Serving V1 válida;
    \item loader aceita apenas Serving compatível;
    \item PostgreSQL recebe a publicação de forma transacional;
    \item Gold e PostgreSQL reconciliam a mesma métrica;
    \item Java responde os endpoints V1 e executa agregações no banco;
    \item frontend usa API real e não soma dados epidemiológicos;
    \item ano, mês, sexo e faixa etária funcionam;
    \item Campos permite drill-down distrito -> bairro/localidade da unidade notificadora;
    \item ausência de cobertura não é mostrada como zero;
    \item Caddy é a única entrada web;
    \item Java/PostgreSQL não estão expostos diretamente à Internet;
    \item ngrok HTTPS publica a aplicação temporariamente;
    \item SSH remoto funciona somente por chave;
    \item smoke E2E valida login -> consulta -> refresh -> logout.
\end{itemize}

\subsection{Execução paralela recomendada}

Dentro dos gates, frentes independentes podem trabalhar simultaneamente:

\begin{itemize}
    \item Pipeline/CNES e faixa etária;
    \item Pipeline/Serving e loader;
    \item Java/Auth;
    \item Java/Analytics;
    \item Frontend/Auth e Dashboard V2 com mocks do contrato;
    \item GeoJSON/artefatos visuais;
    \item Grafana/reconciliação mínima;
    \item NixOS/ngrok/SSH após instalação do host.
\end{itemize}

A integração final só deve ocorrer quando os consumidores e produtores convergirem para os contratos definidos neste repositório.

\subsection{Dívidas aceitas para V1.1+}

WireGuard definitivo, domínio institucional, residência/CIEVS, multi-faixa, RJ completo, Sudeste completo, painel administrativo de usuários, supressão pública de pequenas contagens, observabilidade avançada e automação completa de CI/CD não bloqueiam a NSS 1.0 bootstrap.
