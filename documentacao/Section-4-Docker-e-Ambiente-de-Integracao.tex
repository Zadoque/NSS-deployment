\section{Docker e Ambiente de Integração}

A unidade de versionamento não precisa coincidir com a unidade de execução. A NSS 1.0 é integrada por Docker Compose mantendo imagens independentes.

\subsection{Serviços mínimos}

O ambiente integrado da V1.0 contém:

\begin{itemize}
    \item \textbf{caddy}: única entrada HTTP;
    \item \textbf{frontend}: artefato estático React servido internamente;
    \item \textbf{java}: API Spring Boot;
    \item \textbf{db}: PostgreSQL compartilhado;
    \item \textbf{grafana}: auditoria operacional, sem necessidade de exposição pública;
    \item \textbf{pipeline}: execução batch/job acionada quando necessário, não API pública permanente.
\end{itemize}

\subsection{Rede e portas}

Serviços se comunicam pelo nome do serviço na rede Docker. O Java usa, por exemplo:

\begin{lstlisting}[language=YAML]
jdbc:postgresql://db:5432/nss
\end{lstlisting}

A pipeline utiliza o mesmo PostgreSQL para o schema \texttt{analytics}.

\begin{regra}[Menor exposição]
PostgreSQL e Java não publicam portas na interface externa do servidor. No bootstrap, apenas Caddy é ligado a uma porta local do host para que o agente ngrok a encaminhe. Grafana pode ficar acessível somente por localhost/SSH durante a V1.0.
\end{regra}

\subsection{Propriedade do banco}

Um único PostgreSQL atende o ambiente integrado, mas a propriedade lógica permanece separada:

\begin{itemize}
    \item Java/Flyway versiona tabelas da aplicação, autenticação e refresh tokens;
    \item Python/Alembic versiona \texttt{analytics.*};
    \item Java consome \texttt{analytics.*} para leitura;
    \item pipeline não deve alterar tabelas de autenticação do Java.
\end{itemize}

O isolamento por usuários/roles distintos é desejável e deve ser endurecido antes da entrada de dados restritos. Para a entrega bootstrap, a prioridade é manter o banco não publicado externamente e secrets fora do Git.

\subsection{Imagens}

Cada componente deve produzir sua própria imagem. O Compose de integração referencia tags configuráveis. Isso evita acoplamento entre os repositórios e permite registrar exatamente quais versões participaram de uma release.
