\section{Deployment e Evolução}

A estratégia de deployment possui um estado temporário de bootstrap e um estado definitivo institucional.

\subsection{Bootstrap temporário - NSS 1.0}

Enquanto as portas e o domínio institucional não estiverem disponíveis:

\begin{lstlisting}
Internet
   |-- ngrok HTTPS -> 127.0.0.1:<porta Caddy> -> NSS
   `-- ngrok TCP   -> localhost:22            -> SSH key-only
\end{lstlisting}

O servidor inicia a conexão de saída com ngrok; PostgreSQL, Java e Grafana permanecem não publicados externamente.

\subsection{Estado definitivo}

Após liberação institucional:

\begin{lstlisting}
Publico: dominio institucional -> Caddy -> NSS
Admin:  WireGuard -> SSH key-only
\end{lstlisting}

A branch temporária de ngrok no repositório NixOS deverá então ser removida/desativada e o token revogado.

\subsection{Ambiente integrado}

O \texttt{compose.yaml} deste repositório é o ponto de integração operacional. As imagens continuam pertencendo aos respectivos repositórios. Tags devem ser registradas por release ou SHA para permitir rollback.

\subsection{CI e homologação}

Cada repositório continua responsável pelos seus testes. A release integrada adiciona uma validação ponta a ponta que cobre pelo menos:

\begin{center}
\texttt{login -> dashboard -> API -> PostgreSQL -> refresh -> logout}
\end{center}

Playwright é o mecanismo preferido para o smoke E2E do frontend integrado.

\subsection{Evoluções deliberadamente adiadas}

\begin{itemize}
    \item bairro de residência/CIEVS;
    \item todos os municípios do RJ e demais estados;
    \item seleção simultânea de várias faixas etárias;
    \item administração completa de usuários pela interface;
    \item CI/CD com registry e promoção automática;
    \item observabilidade avançada e alertas;
    \item política definitiva de supressão para publicação pública;
    \item SCD de CNES e outras modelagens históricas não requeridas pela V1.0.
\end{itemize}

\begin{explicacao}[Princípio de evolução incremental]
A NSS 1.0 deve comprovar a cadeia ponta a ponta com um escopo pequeno. Evoluções futuras devem reutilizar contratos estáveis, não impedir a primeira operação real do sistema.
\end{explicacao}
