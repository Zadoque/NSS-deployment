\section{Observabilidade e Debugging}

A NSS 1.0 incorpora uma frente específica de auditoria em Grafana. O objetivo da primeira versão não é observabilidade distribuída completa, mas tornar visível onde uma divergência aparece entre as etapas de dados.

\subsection{Quatro checkpoints mínimos}

Para cada execução relevante, a auditoria deve conseguir comparar:

\begin{enumerate}
    \item \textbf{Bronze}: quantidade de registros recebidos;
    \item \textbf{Silver}: quantidade após limpeza/deduplicação;
    \item \textbf{Gold}: soma da medida publicada;
    \item \textbf{PostgreSQL}: soma equivalente após a carga.
\end{enumerate}

\subsection{Reconciliação mínima}

As invariantes de maior valor para a V1.0 são:

\begin{itemize}
    \item diferença Bronze--Silver explicável por regras de transformação;
    \item \texttt{COUNT} do universo Silver elegível compatível com \texttt{SUM} da Gold quando a semântica exigir conservação;
    \item \texttt{SUM(Gold)} = \texttt{SUM(PostgreSQL)} para a mesma partição e filtros;
    \item falhas de CNES/territorialização contabilizadas como não mapeadas, nunca convertidas silenciosamente em zero.
\end{itemize}

\subsection{Cadeia de diagnóstico}

Quando um valor do frontend parecer incorreto:

\begin{enumerate}
    \item verificar JSON da API Java;
    \item comparar a query equivalente no PostgreSQL;
    \item comparar PostgreSQL e Gold Serving;
    \item comparar Gold e Silver;
    \item comparar Silver e Bronze;
    \item somente então retornar à fonte SINAN/CNES.
\end{enumerate}

\subsection{Escopo adiado}

Não são requisitos para a entrega imediata: Prometheus, tracing distribuído, alertas avançados, DuckDB como datasource de exploração, SLOs formais ou histórico extenso de qualidade. Eles podem ser incorporados quando a V1.0 estiver estável.

\begin{regra}[Auditoria não altera a semântica]
Grafana observa e compara; ele não deve corrigir, reclassificar ou transformar os números oficiais da aplicação.
\end{regra}
